Why it exists

Built for field-facing FAT work, not abstract protocol demos.

IEC101 Master Tester focuses on observable behavior: what went on the wire, what the RTU returned, what the operator can trust, and what should be preserved as evidence.

01

Protocol facts first

COT comes from callback/ASDU facts, ACD/DFC from secondary frame control bits, and unknowns stay unknown.

02

Operator-ready windows

Main values, event log, status history, line monitor, findings, SOE audit, and availability views stay separated.

03

Redundancy observation

NUC workflows track link activity, switchover, continuity, GI observation, and active/standby behavior.

04

Evidence without UI bloat

Live grids use bounded snapshots while protocol evidence is captured separately for golden trace and export.

Clean-room migration

Native IEC-101 is progressing, but still gated.

The native stack already includes FT1.2 parsing, ASDU parsing/encoding, UI mapper integration, an experimental master engine, and protocol evidence recording. The vendor path remains the production baseline until tests prove compatibility.

Workflow

From serial session to reviewable evidence.

  1. Connect

    Use the PLN-style IEC-101 profile or tune serial/link settings for the RTU under test.

  2. Observe

    Watch values, ACD, COT, traffic class, event log, findings, and status history.

  3. Audit

    Use SOE replay, availability telemetry, NUC redundancy, and line trace windows for deeper checks.

  4. Validate

    Capture protocol evidence snapshots to build golden traces for the native stack.
